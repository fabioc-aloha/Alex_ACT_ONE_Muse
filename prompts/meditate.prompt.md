# /meditate

Run the meditation protocol. Identify worthwhile improvements to future work
and leave clean project continuity. Do not write episodic or native memory.

If the generic skill tool is unavailable for the plugin-shipped `meditation`
skill, execute the numbered steps below directly. Do not claim the workflow is
missing based only on the skill tool's inventory.

## Steps

1. Load skill: [meditation](../skills/meditation/SKILL.md)
2. **Review** session evidence, repository guidance, working-tree status, and
   existing continuity records. Inventory changes, open tasks, and lessons.
3. **Evaluate improvements** from demonstrated repeated work or a concrete
   failure. Search existing skills, scripts, tests, and guidance first. Prefer
   correcting an existing capability or adding a regression check over another
   rule. A one-off task does not automatically earn a skill.
4. **Separate authority**: an explicit meditation request authorizes routine
   continuity writes in this repository, subject to its rules. Apply the PII
   filter to every write. Keep separate approval for new behavioral rules,
   unrelated AGENTS changes, and capabilities routed
   through `project-capability-authoring`. Do not commit, push, publish, edit
   installed plugins, or write siblings automatically.
5. **Recommend, then seek approval**: name the evidence, benefit, prior art,
   smallest change, placement, validation, and exact authorization needed.
   Route local skills/scripts through `project-capability-authoring`. Propose
   existing brain-artifact improvements through `compile-brain`. Recommend
   broader canonical adoption or a sanitized Mall candidate only when justified;
   do not submit, install globally, or edit siblings. Analyze real failures
   through cause, pattern, and prevention; put approved prevention in the owning
   skill/test/check, not a new memory report. Implement only approved changes.
6. **Preserve history, then reconcile**: update the existing changelog,
   otherwise `CHANGELOG.md`, with concise completed changes and accurate
   local/unreleased status. Respect release-only conventions; use an existing
   work log/issue or ask before pruning history that has no authorized home.
   Keep required decision rationale in the existing decision-record system.
   Reconcile the authoritative task list (default `TODO.md`); retain
   unresolved work and remove completed items only after preserving closure
   evidence. Account for every original open item; cancellation requires a
   decision. Refresh root `HANDOFF.md` with current state, blockers, next action,
   verification, and links, not history or a duplicate backlog. Check
   `AGENTS.md` stays a stable quick start; repair only necessary continuity
   routes and approved capability links, preserving unrelated guidance. Follow
   existing project conventions. Do not turn recommendations into adopted rules.
7. **Verify and report**: read back saved records, check links, task accounting,
   and applicable repository validation. Report exact writes, skipped
   duplicates, pending approvals, and failures. A partial save is incomplete.
8. **Compact only after verified persistence**, using an available, authorized
   host capability. If unavailable or not authorized, state that compaction
   was not performed. Never claim a slash command ran merely by writing it.

## Anti-pattern guard

Do not create, append, rewrite, migrate, or delete episodic records. Existing
episodes may be consulted as historical evidence when relevant. Do not create
a replacement memory directory, calibration journal, standalone meditation
report, or long session narrative inside the four active records.

No worthwhile capability recommendation is not a reason to skip continuity
cleanup. If state is unchanged, make no duplicate entry or timestamp-only edit.
Do not invent recommendations to make meditation appear productive.
Do not prune or compact after failed persistence. A suggestion to meditate or
session-end signal alone does not grant the write authorization of an explicit
invocation.

**Would revise if**: this fallback diverges from the
[meditation](../skills/meditation/SKILL.md) skill, an unchanged repeat duplicates
history, cleanup loses unresolved work, or the workflow creates memory records
or publishes an unapproved candidate.
